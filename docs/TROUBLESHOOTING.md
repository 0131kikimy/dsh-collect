# 常见问题与排查

**这篇文档解决什么问题：** 面板打不开、采集失败、图片没下来、PDF 生成不了、中文乱码、找不到文件……这里按"症状"列出 10 个最常见的问题，每个都先给 3 个原因，再给能照着点的排查步骤。

> 还没装好？先看 [安装指南](INSTALL.md)。按钮在哪、怎么用，见 [使用手册](USAGE.md)。格式怎么选，见 [格式说明](FORMATS.md)。

## 排查前先做这三件事

1. 点面板右上角的「刷新」，很多时候只是面板状态旧了。
2. 完全退出 DSH 再打开（不是最小化，是关掉重开）。
3. 重新试一次，把**报错原文**记下来或截图（报错文字比"不行"有用得多）。

✅ 检查点：你应该能在报错出现时，把那段文字完整记下来，而不是只说"打不开"。

## 1. 左侧边栏没有「采文」图标

**最常见的 3 个原因**

1. 装完没有重启 DSH。
2. 插件装了但处于禁用状态。
3. 安装其实没成功（地址填错、网络超时、文件没复制对位置）。

**按顺序排查**

1. 完全退出 DSH，重新打开，再看侧边栏。
2. 打开「插件」页，找 `dsh-collect`：找不到说明没装上，回去看 [安装指南](INSTALL.md) 的方式一；找到但显示禁用，点「启用」，再重启。
3. 如果是手动复制安装的，确认 `node_modules\dsh-collect` 里面**直接**能看到 `package.json`，不是又多套了一层文件夹。
4. 打开 DSH 的开发者工具看看有没有红色报错（不懂可以跳过，把报错文字发给帮你的人）。

## 2. 点「采文」面板打不开、空白或一直转圈

**最常见的 3 个原因**

1. 页面加载卡住（DSH 后台还没准备好）。
2. 插件文件和 DSH 版本不匹配（装的是旧版本）。
3. 面板请求本地接口失败，页面停在加载态。

**按顺序排查**

1. 点面板右上角「刷新」；没有刷新按钮就关掉面板再点一次图标。
2. 完全退出 DSH 再打开，等 10 秒后再点「采文」。
3. 换一个页面再切回来（比如先点「设置」再点回「采文」），看是否恢复。
4. 还是空白：卸载后按 [安装指南](INSTALL.md) 重装一次，确保装的是完整文件夹（要有 `lib`、`locale`、`cordis.patch.yml`）。
5. 把"DSH 版本号 + 面板是空白还是转圈"记下来，一起反馈。

## 3. 点「开始采集」没反应，或提示采集失败

**最常见的 3 个原因**

1. 网址格式不对（没有 `https://`、多了空格、是搜索框里的半截链接）。
2. 网站拒绝访问（要登录、有反爬、或者服务器直接返回错误）。
3. 网络或超时：页面太大、网速太慢，超过「超时」设置。

**按顺序排查**

1. 把网址单独复制到浏览器地址栏，能打开再回来粘；确认一行一个，行首行尾没有空格。
2. 一次只留一个网址再试，排除"某一个网址出错导致整批看着像失败"。
3. 确认「原生联网」和「直连抓取」至少有一路开着（默认两路都开），再采一次。
4. 到「设置」区把「超时毫秒」从 20000 调大到 40000，点「保存设置」，再试。
5. 仍然失败：看结果列表里那行的错误文字，它通常会说明是"连不上""被拒绝"还是"超时"。

✅ 检查点：你应该看到结果列表里这一行变成成功状态，显示标题和字数；失败的会带一句红色原因。

## 4. 采集"成功"，但正文几乎为空或只剩标题

**最常见的 3 个原因**

1. 这个网页的正文是脚本动态生成的，直接抓页面拿不到内容。
2. 网站把正文放在特殊结构里，插件没能识别出来。
3. 页面需要登录，抓到的是登录提示页。

**按顺序排查**

1. 先在浏览器里打开这个网页，确认正文确实能正常显示。
2. 先确认网页在浏览器里能正常打开；需要登录的内容，打开「浏览器标签页」开关后，让 AI 用浏览器工具打开该页再采集（面板本身不驱动浏览器）。
3. 如果必须登录才能看，先在浏览器里登录好并打开那篇文章，再用浏览器标签页方式采集。
4. 换一个信息源（同内容的其他网站）通常比死磕一个站点快。

## 5. 图片没下载，或图片显示为坏图

**最常见的 3 个原因**

1. 图片上限设得太小，或者「下载图片」被关掉了。
2. 图片来自防盗链的图床，插件请求被拒绝。
3. 图片本身就是网页里的占位图、懒加载图（地址还不完整）。

**按顺序排查**

1. 到「设置」区确认「下载图片」是开着的，「图片上限」不是 0；改完点「保存设置」。
2. 打开 `采文输出/<文章标题>/图片/` 文件夹，看里面有没有文件：一个都没有，多半是请求被拒；有几个但打不开，多半是图床防盗链。
3. 到结果列表看这篇的"图片数"，是 0 说明一张都没抓到，不是生成时丢的。
4. 对图片多的文章，把「图片上限」调大（比如 50）再采一次。
5. 如果只是生成 Word / PPT 后发现图少了：检查是不是 WebP 图片，这两种格式嵌不进去，会被跳过。

## 6. 选了 PDF，却生成 docx（或 PDF 生成失败）

**最常见的 3 个原因**

1. 本机没有可用的 PDF 转换引擎（DSH 自带组件没找到，也没装 LibreOffice）。
2. 装了但 DSH 是在装 LibreOffice 之前启动的，还没检测到。
3. LibreOffice 装的位置比较特殊，插件自动检测不到，需要在配置里指定路径。

**按顺序排查**

1. 看生成结果行里的提示：如果有"没有找到可用的 PDF 转换引擎"之类的说明，就是原因 1 或 3。
2. 打开 LibreOffice 随便新建一个文档，确认它本身能正常运行（不是装了个坏包）。
3. 完全退出 DSH 再打开，重新点一次「生成」选 `pdf`。
4. 还提示找不到：找到 `soffice.exe` 的完整路径（形如 `C:\path\to\LibreOffice\program\soffice.exe`），让 AI 用 `collect_settings` 把它写进 `pdf` 的 `converter`；或者直接在插件配置里填这个路径。
5. 最省事的替代：先生成 `docx`，用 Word / WPS 打开后「另存为 PDF」。
6. 下载地址：<https://www.libreoffice.org/download/>，默认选项安装即可。

## 7. 找不到生成的文件、找不到 `采文输出`

**最常见的 3 个原因**

1. 找错了"工作目录"——`采文输出/` 是相对于 DSH 当前工作目录的，不是相对于桌面或文档。
2. 在「设置」区改过「输出目录」，文件存到新位置了。
3. 生成还没完成就去找（按钮还在转）。

**按顺序排查**

1. 在面板「设置」区看「输出目录」当前填的是什么（顶部还会显示完整路径）。
2. 在采集结果行里看"保存路径"，它显示的是相对工作目录的路径，照着这个路径找。
3. 记住：生成的文件默认就放在那篇文章的文件夹里，和 `index.md` 在一起，不在 `采文输出/` 的根目录。
4. 直接用生成结果行里的「下载」按钮，这是最不会找错的方式。
5. 在文件资源管理器里搜索文件名（结果行里有文件名），比一层层翻目录快。

## 8. 中文乱码：正文或文件名是问号、方块

**最常见的 3 个原因**

1. 打开文件的软件编码设置不对（尤其是 Excel 打开 CSV、老版记事本打开 md）。
2. 原网页本身不是 UTF-8 编码（国内老站点常见 GBK），插件统一按 UTF-8 解读时会变乱码。
3. 系统缺少显示某些特殊字符的字体。

**按顺序排查**

1. 换一个打开方式：`.md` 用支持 Markdown 的编辑器或浏览器；`.csv` 用 Excel 的"数据 → 从文本/CSV 导入"并选 UTF-8；`.txt` 用新版记事本或 VS Code。
2. 用浏览器直接打开 `index.md` 或生成的 `.html`，浏览器对编码的识别更可靠。
3. 如果只有个别字是方块，多半是字体问题，换台电脑打开或换 `docx`/`pdf` 格式再看。
4. 如果正文从采集那一刻就是乱码（「查看正文」预览里就不对），说明这个网页不是 UTF-8 编码，插件没法正确还原；这种情况请直接看原网页，或换同一内容的其他来源（比如转载页）。

## 9. 开关点不动，或者点了自己弹回去

**最常见的 3 个原因**

1. 这项能力当前不可用（比如没装 computer 操控类插件，或者宿主没提供原生联网）。
2. 保存设置时接口报错，面板自动恢复原状态。
3. 页面状态旧了，和后台不一致。

**按顺序排查**

1. 看开关那一行右侧的能力徽章：显示"未安装/不可用"的，先按提示把对应环境准备好，不是开关坏了。
2. 点右上角「刷新」，再试一次。
3. 重启 DSH 后再试；仍然弹回，说明是保存失败，把页面上的错误提示记下来反馈。

## 10. 「桌面操控」开关打不开（或不敢开）

**最常见的 3 个原因**

1. 没安装 computer 操控类插件（这一项依赖它）。
2. 装了但没启用，或 DSH 没重启。
3. 本来就是默认关闭 + 硬拦截，需要你手动打开。

**按顺序排查**

1. 先确认你真需要它：绝大多数采集场景用「原生联网」+「直连抓取」就够了，不需要动鼠标。
2. 到「插件」页确认 computer 操控类插件已安装且启用，重启 DSH。
3. 回到「信息获取方式」区，手动把「桌面操控」打开；打开后建议用完就关掉。
4. 提醒：它真的会移动鼠标和敲键盘，操作期间别离开电脑，避免误点。

## 11. AI 说找不到工具，或工具调用没反应

**最常见的 3 个原因**

1. 插件没装好或没启用（工具根本不存在）。
2. 装好了但没重启 DSH（工具还没注册进来）。
3. 说法太模糊，AI 没意识到要用这个工具。

**按顺序排查**

1. 确认左侧边栏有「采文」图标、面板能正常打开——这是插件已加载的最直接证据。
2. 重启 DSH 后再试。
3. 直接把工具名说出来："用 `collect_fetch` 采这个网址"，比"帮我看看这个网页"更容易触发。
4. 还是不行：先在面板里手动采一次，确认底层功能正常，再排查 AI 这一侧。

## 12. 采集被拒绝：内网地址、localhost、非 http 链接

**最常见的 3 个原因**

1. 插件默认拒绝本机地址和内网地址（这是安全设计，防止被利用去访问内网）。
2. 地址不是 `http` / `https`（比如 `file://`、`ftp://`）。
3. 地址里带了登录信息或特殊字符。

**按顺序排查**

1. 确认你要采的是公网网址（浏览器里能直接打开、地址以 `https://` 开头）。
2. 内网/本机地址默认不允许，普通采集需求不要用这种方式绕。
3. 去掉地址里多余的空格和中文标点，重新粘一次。

## 最后一招：求助时带上这几样

自己排查完还是不行，把下面这些信息一起发给帮你的人，比只说"用不了"快十倍：

1. 你卡在哪一步（打开面板 / 采集 / 生成 / 找文件）。
2. 页面上的**报错原文**（截图或复制文字）。
3. 插件包名 `dsh-collect`、DSH 版本号、操作系统（Windows / macOS / Linux）。
4. 你试过哪些排查步骤，结果如何。

✅ 检查点：你应该能凑齐这 4 条信息，并且知道问题大致出在安装、采集、生成还是打开文件哪一环。
