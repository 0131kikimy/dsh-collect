# 采文 · CollectKit

**一句话：** 给 DeepSeek Harness 装上这个插件，左侧边栏会多一个「采文」图标；把网址粘进去，它替你把网页的正文和图片取下来，再按你选的格式存成文件。

> 这篇文档解决什么问题：**搞清楚这个插件是什么、能干什么、怎么装、怎么用。** 更细的内容见下面的「文档导航」。

## 插件信息

| 项目 | 值 |
| --- | --- |
| 显示名 | 采文 · CollectKit |
| 包名（插件列表里显示的） | `dsh-collect` |
| 侧边栏标签 | 采文 |
| 面板接口前缀 | `/dsh-collect/api` |
| 运行环境 | DeepSeek Harness 桌面版 / Web 版 |
| 第三方依赖 | 无（插件自带全部代码，不需要 npm install） |

## 能干什么

- **批量采集网页正文。** 一次可以粘多个网址（每行一个），插件会挨个打开，去掉导航、广告、页脚，只留正文。
- **图片一起存下来。** 正文里的图片会下载到本地，网页关掉、断网也能看。
- **生成 9 种格式。** `docx` / `xlsx` / `pptx` / `pdf` / `md` / `html` / `txt` / `csv` / `json`，在面板里点一下按钮就生成。
- **5 种信息获取方式。** 面板采集走「原生联网」和「直连抓取」；另外三个（浏览器标签页、桌面操控、MCP 工具）是给 AI 的授权开关，默认关闭。
- **默认禁止桌面操控。** 「桌面操控」会移动你的鼠标、敲你的键盘，所以默认关闭，并且是硬拦截；确实需要时再手动打开。
- **AI 也能直接用。** 插件给 AI 提供了三个工具：`collect_fetch`（采集网址）、`collect_export`（生成文件）、`collect_settings`（读写设置），你可以直接对 AI 说"帮我采这个网址并存成 Word"。
- **成果都在一个文件夹里。** 默认存到工作目录下的 `采文输出/`，采集结果、图片、生成的文件都在这里，方便统一整理。

## 30 秒安装（最短路径）

1. 打开 DSH，找到「插件」页，点「添加」。
2. 粘贴仓库地址：`https://github.com/0131kikimy/dsh-collect`（把 `<你的账号>` 换成实际地址）。
3. 等提示安装完成，**完全退出 DSH 再重新打开**（重启后才加载新插件）。
4. 看左侧边栏，应该多出一个「采文」图标。

三种安装方式（插件页添加 / 本地文件夹安装 / 手动放进 profile）的完整步骤、卸载方法，见 [安装指南](docs/INSTALL.md)。

✅ 检查点：你应该看到左侧边栏出现「采文」图标，点开后页面标题是「采文 · CollectKit」。

## 5 步上手

1. **点图标。** 左侧边栏点「采文」，打开面板。
2. **粘网址。** 在「采集」区把网页地址粘进去，一行一个（也支持用逗号或空格隔开）。
3. **开始采集。** 点「开始采集」，等提示"正在采集第 n/m 个"走完。
4. **选格式、点生成。** 在「生成文件」区点一种格式（默认是 `docx`），再点「生成」。
5. **找文件。** 打开工作目录下的 `采文输出/`，每篇文章一个子文件夹，正文、图片和生成的文件都在那个文件夹里。

每个按钮的具体说明见 [使用手册](docs/USAGE.md)。

✅ 检查点：你应该在 `采文输出/` 下看到至少一个文件夹，里面有 `index.md` 和 `图片/` 文件夹。

## 功能表

| 功能 | 在哪里 | 说明 |
| --- | --- | --- |
| 采集网页正文 + 图片 | 面板「采集」区 | 支持多个网址；正文自动去掉导航、广告、页脚 |
| 查看采集结果 | 采集结果列表 | 显示标题、来源域名、字数、图片数、获取方式、保存的相对路径 |
| 展开正文预览 | 结果行的「查看正文」 | 只读预览，最多显示 4000 字 |
| 生成 9 种格式文件 | 面板「生成文件」区 | 先选「导出对象」→ 选格式 → 点「生成」→ 得到文件名、大小和「下载」按钮 |
| 切换信息获取方式 | 面板「信息获取方式」区 | 5 个开关，改动立即保存，失败会自动恢复原状 |
| 调整输出与采集参数 | 面板「设置」区 | 输出目录、单页最大字节、超时毫秒、图片上限、下载图片；改完点「保存设置」 |
| 让 AI 直接采集 | 对 AI 说话 | 工具 `collect_fetch` |
| 让 AI 直接生成文件 | 对 AI 说话 | 工具 `collect_export` |
| 让 AI 读写插件设置 | 对 AI 说话 | 工具 `collect_settings` |

✅ 检查点：你应该在面板里看到「采集」「生成文件」「设置」这几个区，和表里对应得上。

## 能力对照表

| 信息获取方式 | 是否需要额外插件 | 风险等级 | 默认状态 |
| --- | --- | --- | --- |
| 原生联网 | 不需要（用 DSH 宿主自带的联网能力；宿主没提供时这一行显示"不可用"） | 低 | 开启 |
| 直连抓取 | 不需要（插件自己访问网站） | 低 | 开启 |
| 浏览器标签页 | 需要宿主里有浏览器标签页类工具（通常由其他插件提供） | 中（能读到你浏览器里已打开页面的内容） | 关闭 |
| 桌面操控 | 需要已安装 computer 操控类插件 | 高（会移动鼠标、敲键盘，可能误点） | 关闭（硬拦截，要手动打开） |
| MCP 工具 | 需要已安装并连接 MCP 数据源插件 | 中～高（取决于所连插件能做什么） | 关闭 |

"硬拦截"的意思是：开关关着的时候，即使 AI 主动想用桌面操控，插件也会直接拒绝，不会偷偷动你的鼠标。

还有一点要分清：面板上的「开始采集」只会用「原生联网」和「直连抓取」这两路去取网页；后三个开关不会替面板抓网页，而是决定 AI 在面板抓不到时能不能改用对应的工具。另外「原生联网」和「直连抓取」不能同时关闭，至少要留一路。
